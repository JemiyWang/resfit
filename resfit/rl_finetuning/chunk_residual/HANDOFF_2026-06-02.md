## 2. Bug 修复(本轮两个真 bug)
1. **dexmg 双臂 grasp 判定死**:`robot.gripper` 是 **dict**,`for g in robot.gripper` 迭代出**字符串键**,`_check_grasp(gripper="right")` 恒 False(**env 自带 `_check_first_piece_is_assembled` 也踩了**)。后果:stage 1 永不触发、stage 2 退化成"只看 xy 靠近"。修:`stage_detectors._grasped` 对 dict 取 `.values()`,`threepiece_stage` 显式 `AND not grasped` 补回释放语义。真环境瞬时探针确认 stage 1 现在出现(344/1500 步)。

## 3. stage 工具链怎么用
- **检测器在 worker 内跑**:`dexmg.py` 的 `RobosuiteGymWrapper.step` 调 `get_stage_detector(env_name)`,有则把 `int(stage)` 放 `info["stage_id"]`,经 AsyncVectorEnv batch 透出。无检测器的任务(BoxCleanup 等)不出该键,优雅退化。
- **stage-balanced**:`train ... --stage_balanced`。n-step 由 `MultiStepTransform` 在 add 时烤进 transition(采样 identity),故按 stage 配额任意选索引**不破坏 n-step**(已从源码确认)。默认各 present 阶段平分;稀少阶段不足配额时有放回。
- **诊断**:训练每到 eval 节奏打印 `[stage-diag] diag/count/stageK=.. residual_norm/stageK=.. target_q/stageK=..`。

## 4. 关键设计事实(踩坑必读)
- **默认是 `AsyncVectorEnv(context="spawn")`**(连 num_envs=1 也是)→ robosuite env 在**子进程**。主进程**不可能** unwrap 到 `_check_*`;且 `RobosuiteGymWrapper.get_wrapper_attr` 拒绝转发,`vec_env.call("_check_success")` 也报错。所以 stage **只能在 worker 内算 + info 透出**。(`unwrap_base_env` 已证明是死路,已删。)
- **ThreePiece stage 是按 piece_1 进度 + 最终成功划的**:piece_2 的抓/搬**没有独立子阶段**,折叠进 stage2→3。所以"残差要补的 stage2→3"实际是一大段动作。
- chunk 20 步**开环执行**把基座从 BC 的 62% 砍到 ~30%(无重规划)。这是 harness 代价,和"RL 学不学得动"是两个独立问题。

## 6.5 ⭐ 奖励整形改模式选择 + potential-based shaping(✅ 已实现,2026-06-02 晚 TDD)

> **更新**:本节设计已全部落地。`chunk_env_wrapper.shaping_reward(start,end,*,mode,bonus,gamma,done)` 三模式 `none|staged|potential`;`resolve_shaping_mode` 解析 flag(canonical `--reward_shaping` 优先,`--staged_reward` 别名);train 加 `--output_dir`(并行 run 必须分目录,否则抢 `best.pt`)。**72 测全绿**(下方 4 个必做点均有测试钉死,尤其 done 置零符号 + telescoping)。
> **A/B 已起**:staged(GPU3,outputs_chunk/)vs potential(GPU6,outputs_chunk/potential/),配置仅差 shaping 模式。早期(20k):两者都把 critic 救出恒0,但 eval 同样早塌。**target_q 签名**:staged 反向(stage0最高,净加 bonus 可收);potential 呈 −bonus·stage 线性下移,还原 Q_orig≈平的~0.2=真实成功率 → 证实 PBS 实现正确,且 critic 有信号≠学得动(残差仍漂移)。详见记忆 `project_dexmg_stage_detector`。
> 下方为原始设计,保留备查。

**目标**:把现有 staged 稠密奖励重构成 `none | staged | potential` 三选一,新增 potential-based shaping(PBS)模式,用于干净 A/B。

**目标**:把现有 staged 稠密奖励重构成 `none | staged | potential` 三选一,新增 potential-based shaping(PBS)模式,用于干净 A/B。

**两模式本质不同(这是做成模式的理由)**:
- `staged`(现有):`F = bonus·max(0, Δstage)`,带 max-so-far 闩锁 → 一 episode 累计 `bonus·最高stage`。**净加正奖励**,直接造信号(16 个卡 stage2 的失败轨迹 → +2·bonus),但**改变最优策略**,有 reward-hacking/早停风险,bonus=1.0 时 Q 被抬 ~5×。
- `potential`(新增):`F = bonus·(γ·Φ(s') − Φ(s))`,Φ=stage。**Ng 1999 定理:不改变最优策略**(整轨迹 shaping 折现后 telescoping 成与策略无关常数)→ 无早停偏置;仍给 critic 逐步非零梯度(critic_loss 脱离 0),但**不净加奖励**,只把信用提前发放。

**PBS 必须做对的 4 点(否则失去理论保证)**:
1. **终止置零 Φ(terminal)=0**(最易错):done 时 `F = bonus·(γ·0 − start) = −bonus·start`,负收尾抵消累积。漏了就退化成普通折现进步奖励(又有早停风险)。wrapper `step` 有 `done`(=term|trunc),按它置零(与 critic 对 Q-target 的 bootstrap 一致;truncation 那点极小瑕疵可接受)。
2. **传 γ,n-step 下是近似**:用 `args.gamma`(每 chunk)作 PBS 的 γ;shaping 在 add 前折进 reward → MultiStepTransform 会一起烤 n-step,严格 telescoping 不精确,有微小残余偏置(staged 无此问题)。
3. **用闩锁后的 stage_id 当 Φ 是 OK 的**:stage_id(max-so-far)已写进 `observation.stage_id`、是 agent 看到的增广状态一部分 → Φ 仍是状态函数,不变性对 agent 实际 MDP 成立。
4. **eval 恒 none**(指标纯净);**staged 行为逐位不变**(现有 5 个 `staged_bonus` 单测 + 4 个 wrapper 集成测试必须保持绿)→ 模式分发里 staged 分支调原公式。

**接口设计(建议)**:
- 纯函数 `shaping_reward(start, end, *, mode, bonus, gamma, done) -> float`(放 chunk_env_wrapper),三分支;`staged_bonus` 保留供 staged 分支复用。
- wrapper `__init__` 加 `reward_shaping_mode: str="none"` 与 `gamma`(potential 用);`step` 把现在那行 `staged_bonus(...)` 换成 `shaping_reward(...)`。
- flag:`--reward_shaping {none,staged,potential}`(canonical);`--staged_reward` 保留为映射到 `staged` 的兼容别名;`--stage_reward_bonus` 作两 shaping 模式共用幅度旋钮。
- **先 TDD `shaping_reward`**:重点钉死 (a) potential 的 **done 置零符号**、(b) Δ=0 / 回退时各模式的值、(c) staged 分支与旧 `staged_bonus` 逐位相同。

**预期管理**:PBS 比 staged"温和"(不净加奖励),可能单独不足以把 critic 从 0 拉起;三选一跑完大概率结论是 staged 给信号猛但可能 hack、potential 安全但可能不够力 → 真要稳可能是 **potential + advantage-gating** 或 **staged + 调小 bonus**。跑出来再定。

## 7. ⭐ 奖励稀疏度探针结果(2026-06-02,已跑)+ 下一步

**探针** `verify_reward_sparsity.py`(base 零残差,25 episode,逐 episode 最高 stage):
```
最高 stage 分布: {0:2, 1:2, 2:16, 3:5}
到过 stage>=1: 92% | 到过 stage>=2: 84% | 完整成功 stage3: 20%
```
**结论**:**64% 的 episode 恰好卡在 stage 2**(piece_1 放好,piece_2 没完成)。这正是 HER 的完美场景——这些"对 stage2 成功、对最终失败"的轨迹,稀疏奖励下全是 0(critic_loss≡0 的来源),用 HER 对 stage2 目标重标成功就变成大量正样本喂 critic。**瓶颈精确定位在 stage2→3(整个 piece_2 操作,目前折叠成一大跳)**。base 完整成功 20%,再次印证 chunk 开环把基座压到 ~20-30%(单步是 58%)。
→ **HER 明确值得做,不是"该先修开环"那种情况。**

### 下一步(按优先级,数据已支持)
1. **(推荐先做)把 stage 2→3 拆细**:加 "piece_2 已抓起" 子阶段 → ThreePiece 变 5 段(TDD,跟 stage1 同套路),让 HER 在瓶颈段有**梯度化信用**而非只有"到2/到3"两档。
2. **HER-like stage relabeling(§18.5,4b)**:失败但到 stageK 的轨迹,对 stageK 目标重标成功 → 喂 critic 稠密按阶段奖励。**直击根因**;stage 标签已就绪。
3. **advantage-gated residual(§18.2)止损**:critic 没用时执行纯基座,别让残差毁基座。或调小 action_scale / 加 BC-identity 锚定。重跑后看 **critic_loss 是否不再恒 0、success 能否超过基座 ~20-30%**。
4. **stage-conditioned critic(4a)暂不优先**:没奖励可学时表达力强也白搭;等 2/3 让 critic 有信号后再说。
5. 项目最终目标仍是 **flow vs raw 的 chunk 级 A/B**——要等 RL 在某任务上**先学得动**才有意义。ThreePiece 当前学不动;可考虑先在更容易的任务(基座开环成功率高、奖励没那么稀)上验 stage 工具链 + flow。
